# 精讲稿写作规范（ECON102）

## 目标
把每一页幻灯片的英文原文，改写成**中文逐页精讲**，让一个没上过课的学生读一页就能懂这一页在讲什么、为什么重要、怎么用。

## 输入
- `D:\WILL\ECON102\work\<tag>_full.txt`：UTF-8，每页一段，格式
  ```
  === P3 (412 chars) ===
  （该页全部文字，含标题、正文、表格文字、图注）
  ...
  ```
  页数 = 最后一个 `=== Pn` 的 n（可用 `work\<tag>.json` 里的 `count` 核对）。
- `D:\WILL\ECON102\work\<tag>.json`：`{"count":N,"slides":[{"n":1,"text":"...","pics":2,"notes":""}]}`，
  `pics` 是该页图片/图表数量，`notes` 是演讲者备注（常含老师口头补充，务必吸收）。
- 幻灯片原图在 `D:\WILL\ECON102\assets\<dir>\slide-NNN.png`。需要时可以用 read_image 看某几页的图，
  **但不要逐页看图**（太慢），只在文字读不通（例如只有一张图、或有坐标轴/数值需要确认）时看关键页。

## 输出
写文件 `D:\WILL\ECON102\src\<tag>.md`（UTF-8，用 write 工具一次写完或分段写完再合并）：

- 只有 `### N` 分块，N 从 1 到 count，**一页一块，顺序不能乱，不能跳页，不能合并两页**。
- `### N` 后面直接写该页的讲解（不要空行也行，但建议空一行）。
- 不要在文件开头加标题、不要写目录、不要写"第X讲"之类的头部，`### N` 之前不要有任何内容。

## 讲解内容（每页按这个顺序想，但不必分段罗列）
1. **这一页在干什么**：一句话点明（是定义页？例子页？图表页？过渡页？公式页？）。
2. **概念/机制**：把英文要点翻成中文并讲清因果链，不要只翻译字面。
3. **例子与数字**：课件里出现的人名、公司、金额、百分比、年份、公式，全部保留并解释其含义。
4. **老师补充**（重要）：用「为什么这样设计」「常见的错解」「考点」的方式补一两句，帮学生把这页接到整门课的骨架上。

## 文风
- 你是**讲课的教师**，直接对学生说话。可以用「我们」「注意」「这里容易错」。
- 用 `**加粗**` 标关键术语（每页 2–5 处，不要满屏加粗）。
- 列表用 `- `；步骤用 `1. `；原文引用/结论用 `> `。
- 课件里的表格：用 markdown 表格复现（`| a | b |` + `|---|---|`），并在表下解释怎么读。
- 公式：写成纯文本形式，如 `MR = P(1 + 1/ε)`、`MRS = MUx/MUy`、`P = a - bQ`。
- 英文术语第一次出现时给中文 + 括号英文，之后只用中文。

## 篇幅
- 一般页 **120–300 个汉字**；核心概念页/图表页可到 **400**；过渡页、纯图片页 **60–120** 即可。
- 宁短勿水：不要写「这一页非常重要，我们要认真理解」这种空话；每句话都要有信息。

## 禁止
- 不要编造课件里没有的数据、人名、案例（宁可少写）。
- 不要把整段英文照抄进正文（术语、书名、公式除外）。
- 不要输出「（此处为图片）」这类占位符；图片页要说明图画的是什么、怎么读。
- 不要用 ``` 代码块包裹正文。

## 纯图片页的处理
若某页 `text` 极短（<20 字符）而 `pics>0`，用 read_image 看一眼那张图，然后用文字描述图的构成（坐标轴、曲线、区域、箭头）与读图结论。若 `pics==0` 且无文字，就写这是过渡/空白页，一句话带过并承接上下页。

## 完成后自检
1. 文件里 `### N` 的个数 == count，且 N 连续。
2. 随机抽 3 页，确认讲的不是同一段套话。
3. 报告：文件路径、页数、总字数、最长的 3 页与最短的 3 页页码。
